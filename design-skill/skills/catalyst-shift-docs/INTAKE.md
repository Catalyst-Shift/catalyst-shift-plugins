# Intake — what to ask when context is thin

When a teammate invokes this skill with a one-line ask ("make a proposal for Acme"), you need more before you can write a credible doc. Ask in **one bundled message**, not piecemeal.

## Universal questions (always ask if missing)

1. **Client / company name** — and one line on what they do.
2. **MSP size** — annual revenue band ($500K–$3M primary / $3M–$10M extended / out-of-scope), endpoint count, headcount.
3. **Stack** — PSA (ConnectWise / Halo / Autotask / other) + RMM (NinjaOne / Datto / Atera / other) + ticketing.
4. **Decision-maker** — name, role (owner / COO), what they care about most.
5. **Stage** — first contact, post-discovery call, post-signed engagement, or delivery phase.
6. **Format preference** — HTML/PDF, PPTX, DOCX, Markdown. Default per the table in `SKILL.md`.

## Doc-specific add-ons

### Proposal
- Which tier are we proposing — **Foundation** (M.01–M.03 · $12,500 setup / $3,200 MRR), **Growth** (M.04–M.05 · $5,500 / $1,600 MRR), or **Full Stack** (all five · $16,500 / $4,500 MRR)? Custom scope?
- Which specific modules (M.01 QBR Automation / M.02 Churn Early Warning / M.03 Proposal Generation / M.04 Pipeline Visibility / M.05 Content & Authority)?
- Is this a **design-partner deal** (first 10 customers — reduced setup, $1–2K MRR, 12-month commit, case-study rights)?
- Is the prospect an **IBPI member** (15% setup discount / 10% Y1 MRR discount)?
- Specific outcomes to guarantee in writing — what does success look like at 30 / 60 / 90 days per module?
- Integration scope — which systems does the OS need to read/write, and who owns access on the customer side?
- Any client-specific constraints (timeline, compliance — HIPAA / CMMC / SOC 2 — geographic, multi-tenant)?

### SOW (statement of work)
- Has the proposal been signed? If not, write a proposal first.
- Final setup + MRR + payment schedule (default: setup 50% on signing / 50% on first module go-live; MRR billed monthly in arrears).
- Final guaranteed outcomes per module — must be specific and measurable.
- Start date and integration kickoff date (target: onboarding within 5 business days of signing, first module outcome inside 30 days).
- Who's the CS lead (Kevin product/engineering / Lucas revenue & relationship / Keith COO & delivery)?

### Discovery report
- When was the discovery call? Pull from transcript or notes.
- What problem(s) did the MSP surface? Use their words. Map to module(s) where there's clear fit.
- What's the recommended path — Foundation / Growth / Full Stack / single-module pilot?
- Did we commit to follow-up materials by a specific date?

### Sales deck
- Audience — single owner, leadership team, IBPI peer group, conference room?
- Length — 5 / 10 / 15 / 20 slides?
- Are we leading with a single module (typically M.01 QBR Automation as the wedge), the Foundation tier, or the full operating layer?
- Are we including the design-partner offer?
- Any specific case study / proof points to feature? (If none, lean on the methodology, the modular framework, and the guarantee structure — never fabricate.)

### Client deliverable
- Which module is this for (M.01–M.05) and which deliverable inside that module?
- What's the actual content the teammate has? (The skill formats and brands; it doesn't invent the work product.)
- Internal review or client-final?

### Case study
- **Has the engagement closed and have outcomes been measured against the SOW?** If no, do not write a case study — propose a "principles in practice" or "design-partner update" doc instead.
- Client approval to use their name? If not, write it anonymized (industry + size band + region).
- Specific metrics — renewal rate, churn risk caught, proposals/week, forecast accuracy, pipeline velocity, content reach. Module-specific.

### One-pager
- What single thing is this for — a module (M.01–M.05), a tier (Foundation / Growth / Full Stack), the design-partner program, the IBPI program, a vertical-specific play?
- Where will it be used — email attachment, in-person leave-behind, conference handout, IBPI peer-group share?

### Internal doc
- What kind — meeting notes, retro, decision memo, planning doc?
- Audience — just the three principals, or extended team / advisor / IBPI?
- Action items vs reference?

## When the teammate gives you a transcript

Read it once. Pull:
- Decision-maker name + role + what they kept coming back to
- Specific pain language they used (quote it back in the doc)
- Stack mentions (PSA / RMM / ticketing) — even partial
- Any explicit asks ("send us a proposal by Friday", "we need this on the next leadership sync")
- Any deal-breakers (budget cap, timeline, must-haves, compliance)

Then ask only what's *not* in the transcript.

## When the teammate gives you a prior doc to remix

Read it. Note what's reusable (structure, voice, sections) and what needs to change (client name, MSP size, stack, scope, modules, fees, dates, specific outcomes). **If the prior doc uses v3.x language** (Diagnostic / 60-day Foundation / 90-day Operating Layer / Signal Sprint / fractional CRO / "growth strategy firm") flag it and rewrite to v4.3 (Foundation / Growth / Full Stack tiers, five modules, vertical-first MSP firm). Confirm the new client + scope, then write.
